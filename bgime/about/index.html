版本、许可与参与开发

本文档适用于 Draftor Alpha 3 中使用的 bgIME。版本依据是发布标签 v0.1.0-alpha.3，对应提交 f18939f8880e2278c231739d553fbf983c19e0f6。教程和接口中的源码引用固定到这个提交。

这些模块版本未因 Alpha 3 的产品集成而统一改号。kCompositionLearningApiVersion 是源码中的组合学习接口标记，值为 2，也不是一个新的 bgIME 发行版本。

版本定义见 Core CMake、Extension CMake、组合学习声明和产品版本约定。

源码与资源获取

源码随 Ohhellboy/Draftor 维护。初次运行使用快速开始里的固定标签；需要实际输入词库时，按资源页面获取匹配的文件。文档所在网站与草稿机安装入口共用域名，路径独立为 /bgime/。

Alpha 3 的产品验证范围见 ALPHA3_VALIDATION.md。早期的查询与取字改进、对照测试和设备移植过程保留在性能记录、版本说明及微雪版本历史中；学习接口以这里所指 Alpha 3 源码为准。

Host 示例不依赖 Draftor 的屏幕字体。你的界面可以采用自己的合法字体，不需要为了使用 Core 而引入草稿机的菜单字形资源。

报告问题

在 GitHub Issues提交问题时，请说明你正在完成的操作，以及预期和实际结果。附上源码提交、所用示例或模块、操作系统与编译器版本、完整命令和错误输出。资源问题还应说明资源包来源及核对后的身份。

个人词频、用户文稿和设备备份通常不需要公开上传。优先用小型测试资源构造可重现输入；学习问题可以描述状态转换与错误码，避免把个人记录当作必要附件。

参与开发

先运行相关 Host 示例，再提出范围清楚的修改。文档改进适合补充首次接入者容易遗漏的调用顺序、缓冲区有效期和失败处理；新平台适配需要说明目标系统、文件接口、调度方式及验证范围。

补充完整独立学习示例前，需要先讨论可公开的选词资格入口及宿主的调用责任。示例应使用与 Alpha 3 一致的记录规则，并覆盖跨方案共享、关闭重开和保存失败处理；当前接入范围见选词学习。
