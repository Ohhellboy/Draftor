bgIME 嵌入式中文输入引擎

bgIME（大鹅输入法）是面向资源受限设备的 C++17 中文输入引擎，支持全拼、小鹤双拼和五笔86。本文档适用于 Draftor Alpha 3 中使用的 bgIME。

构建与运行示例 →API 参考

三个 Host 示例使用人工测试资源，可独立验证输入、候选与提交流程，无需开发板或正式词库。

能力边界

全拼与小鹤双拼支持逐键编辑、编码切分和多词组合提交。五笔86提供编码规则与直接查询适配，也可使用 Extension 的 DirectExact 组合路径。选词学习根据符合条件的选择事件更新个人计数，并用于候选排序，记录条件见选词学习。

引擎输出 UTF-8 字节串，不负责字形绘制、光标移动或文档保存。仓库未提供操作系统输入法安装包或适用于任意平台的完整界面。

模块划分

源码保留 HanIME 命名。Core 与 Extension 可通过 CMake 构建为库，宿主按接入路径链接所需模块。Host 示例是使用这些库的 C++17 命令行宿主。

模块 职责 接口与示例
Core 共享词条与方案索引、候选查询与排序、输出解析、提交和个人记录 Core 示例
Extension 全拼与小鹤双拼解析、编码切分、组合选择及提交适配；DirectExact 精确查询路径 组合输入示例
Wubi 五笔86编码编辑与校验、Core 直接查询绑定 Wubi 接口

Core 可独立使用，不要求经由 Extension 或 Wubi。五笔两条路径的依赖与调用差异见输入方案与示例。

架构特性

各方案拥有独立的编码索引，通过 RuntimeLexemeRef 引用当前共享资源中的词条。共享词条记录提供 StableLexemeKey，以稳定身份关联词汇数据、输出形式与个人学习状态。个人记录按词条命名空间和完整的稳定词条键定位，全拼、小鹤双拼和五笔86复用同一份状态；运行时引用不作为跨资源版本的持久化身份。

相同显示文字不必然代表相同词条身份。更换资源时需核对命名空间、词条身份及资源兼容关系，不能按显示文字合并个人记录，详见词条身份与状态结构及资源结构与身份绑定。

  • 按需读取与验证。 ResourceReader 提供外部存储访问，资源打开、校验和挂载代次决定后续查询的有效性。正式资源使用配套身份描述与验证材料。
  • 有界工作与可恢复状态。 WorkBudget 约束单步读取次数、字节数及逻辑工作量，宿主调度状态机至完成或终止。该预算不构成硬实时保证；缓冲区容量约束也不表示完全无动态分配。
  • 分阶段的状态生命周期。 候选呈现、选择确认和文本提交各有状态与有效期。输入编辑、资源失效或排序过期后，应按相应接口刷新候选或重新选择，见宿主集成。

Draftor 产品集成

Draftor（草稿机） 将 bgIME 与键盘、编辑器、屏幕及 TF 卡连接。Alpha 3 微雪设备的集成还负责确认可学习的选词事件、调度后台保存及显示保存状态。

候选布局、快捷键和保存操作属于产品界面。其他宿主可采用不同交互，但接入时应遵守接口的数据有效期、串行调用和提交约定。

验证与支持范围

使用方式 已有验证范围 集成条件
Draftor Alpha 3 微雪 ESP32-S3、ST7305 4.2 英寸反射屏设备上的产品集成 资源、调度与学习代码依赖 Draftor 产品环境
三个 Host 示例 macOS 上的 C++17 命令行程序，使用 POSIX 文件接口 覆盖基本输入、候选与提交；未完整演示 Alpha 3 学习接入
其他平台 Core 可独立构建；未提供通用插件 ABI 或各平台安装包 需适配存储与调度并验证目标硬件；Windows 原生运行不在现有示例验证范围内

早期对照测试的版本、硬件和计时范围见性能记录。Alpha 3 查询与取字耗时需结合目标设备、资源、存储及预算测量。
