# ROM 状态解析修复（2026-11-19）

`src/rom.js` 现在按准确 esptool 5.3.1 `check_command()` 处理 ROM 尾部：第一个字节是成功／错误状态，第二个是错误原因，后两个是保留字节。只有状态非零才报 `ROM_STATUS`；原因字节在成功时不决定结果。真实 `00 00 FF FF` 应答可被接受。

方向、命令号、声明长度、实际完整长度、ASCII MD5、身份、安全配置、分区、OTA、备份和编译期写入锁均保持原有检查。非零错误状态、非空截断帧和异常帧仍会进入不可继续的终止状态，不重试。

新增 `tests/rom-status.test.mjs`。56 项针对性回归通过，包含本机私有真实回应重放、非零错误状态、全部 0–43 字节截断、方向／命令／长度异常、非法 MD5 和默认写入锁；另 6 项既有相关 ROM 回归通过。没有重跑整套旧软件验收。

真实回应不进入仓库。以环境变量 `DRAFTOR_CAPTURED_ROM_MD5` 指定本机私有 44 字节回应文件，可运行实际回应重放；没有提供该文件时，只跳过该项真实重放，合成回归仍运行。测试不打开设备。

默认 `npm run build` 的 `hardwareUpdateWrites=false`、`hardwareFreshWrites=false`。对应源码归档与站点包包含修复；原 R1 交付包保留，不覆盖历史证据。
