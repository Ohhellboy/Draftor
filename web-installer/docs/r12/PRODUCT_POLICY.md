# R12 安装保护与产品策略

基线：R11 `WINDOWS_UNBLOCKED_PUBLIC_BETA_DEPLOYED`；源码 `385a584bc24ac4f31c93526e1f327f8451437eb7`，Pages `8ca75a4b71d104407098d54001bcbae8dd38e898`。R12 仅本机隔离分支和软件候选；不部署、不访问真实设备。首页及素纸朱印样式保留。

## 已落实的保护责任

| 内容 | 谁管理 | 正常安装前的保护 | 不作出的保证 |
| --- | --- | --- | --- |
| 准确 Alpha 3 bootloader、分区、初始 OTA、App | 安装器的固定大小/SHA-256/MD5 发行清单 | 安装前加载并验证；写后 ROM MD5、分区/OTA/保护区校验 | 不接受未知旧 App，不升级其他版本 |
| 准确厂家系统的固定区 | 固定官方提交和镜像摘要；在本机候选中随资产管理 | 三段原设备 ROM 指纹与官方镜像重建整片摘要一致 | 未扩展到其他厂家批次 |
| 厂家 NVS/PHY 可变区 `0x9000..0x10000` | 用户私人数据，即使只是厂家校准也不假定可丢弃 | 慢读 28 KiB + ROM MD5，写入小型保护 JSON；读回核验后才允许清除 | 不自动转换为 Draftor 设置；恢复会回厂家原系统 |
| Alpha 3 NVS、配对、设置、内部文稿/学习、非活动 App、ime_ro、ffat、coredump、未使用槽尾 | 原板上的现有状态 | 只写 App 实际扇区；保护范围是 `[0,0x10000)` 与 `[0x3e6000,0x1000000)`，写前后 ROM MD5 一致 | 小型保护文件不是这些区域的异机副本；硬件损坏或越界数据损坏仍需完整备份 |
| Alpha 3 App 最后扇区的 1,120 字节尾部 | 可能非 FF，不能假定可丢弃 | 慢读并保存到保护文件；异常恢复时精确补回 | 正常 App 重装仍按原 ROM 写法擦该扇区，不声称全槽字节不变 |
| TF 文稿、私人学习数据和资源 | 用户保留；公开可重建资源由 TF 下载流程提供 | 文稿先保存；完全断电后取出 TF；安装器不读写 TF | 不把 TF 公共 LearningIndex 当作用户学习记录，不格式化原卡 |

实际依据：固定发行源码中的 `partitions/B.csv`、`platform/ws_keyboard_nvs_guard.cpp`、文稿存储接口，以及现有安装器的精确写入范围。NVS 防自动格式化保护说明其内容不能当成可重建缓存。对内部数据不尝试解释、迁移或重建；完整保留写入范围之外的原字节。

## 正常路径

首页连接 → 合并实物条件确认 → 浏览器串口选择 → 程序识别厂家 / Alpha 3 app0 → 展示具体影响 → 保存小型保护文件并安装。

保存按钮直接调用原生 `showSaveFilePicker`，不先等待网络。选定文件后 `createWritable → write → close → getFile → arrayBuffer`，比较实际落盘读回字节、规范 JSON、SHA-256 和本会话保护内容，才授予一次安装权限。文件句柄不持久化；关闭时清除私有引用。读回不是断电后的物理介质持久性证明。

厂家按钮明确写“保存保护文件，清空内部 Flash 并安装”，不会把清除同意藏在通用下一步里。备份确认不再被设成假的 true：`ProductInstallSession` 使用独立且不可伪造的当前会话保存凭据；R11 `PublicInstallSession` 仍要求完整 ZIP 和离线工具，针对性旧回归继续验证它。

不支持自动文件保存 API 时，降级为“小型保护文件下载 → 回选实际保存文件 → 明确安装”。该路径会超过 6 次点击，不把一次点击下载当作已保存。取消选择、磁盘写满、拒绝权限、写后读回不符均不会开始 Flash 写入。

File System Access 依据：[Chrome 官方 API 说明](https://developer.chrome.com/docs/capabilities/web-apis/file-system-access)、[createWritable](https://developer.mozilla.org/en-US/docs/Web/API/FileSystemFileHandle/createWritable)、[getFile](https://developer.mozilla.org/en-US/docs/Web/API/FileSystemFileHandle/getFile)。此 API 是保存小文件的能力，不扩大 USB 或 Flash 权限。

## 失败与恢复矩阵

| 发生阶段 | 程序结果 | 用户安全下一步 |
| --- | --- | --- |
| 未连接 / 原生选择取消 | 零写入，不隐式重连 | 明确重新开始连接 |
| 前检、保存、读回或最后复核失败 | 停止、关闭；零写入 | 保留原因，重新检查条件；通信或安全异常先排障 |
| 已发 FLASH_BEGIN、数据中断、校验失败 | `POSSIBLY_PARTIAL`；不重试、不换槽、不复位 | 不直接安装或普通启动，保留保护文件，手动 ROM 后走“安装中断处理” |
| 部分 App 且无保护文件 | 未知当前 App 拒绝 | 使用独立完整备份；不能猜原板或跳过状态识别 |
| 有厂家保护文件且原板身份、安全、容量匹配 | 只读地用准确官方镜像 + 保存的 28 KiB 重建原整片；全 MD5 和原状态分类必须一致 | 下载重建 ZIP 后，独立明确同意整片恢复；回厂家演示后再独立开始安装 |
| 有 Alpha 3 保护文件且所有原私人区域仍匹配 | 异常路径才慢读当前整片并核对当前前后 ROM MD5；仅替换固定旧 App 和保存的 1,120 字节；重建整片 MD5 必须等于安装前 | 保存重建 ZIP，使用对应离线工具的原板完整恢复；之后另开正常安装会话 |
| Alpha 3 私人区域变化 / 原板不同 / 保护文件损坏 / 官方文件不匹配 | 拒绝重建和恢复，零写入 | 保留当前数据和独立备份；不覆盖更新后的私人状态 |

重建过程始终只有读权限。最终恢复继续使用已有 `RecoverySession` 和 `S3Rom.grantRecovery/restoreRecovery`：验证整片包、原板、安全和容量，独立确认，单次 0x0/16 MiB，写后全 MD5/分区/OTA，无 stub/自动复位。未给未知状态授予安装权限，未新增写入命令、地址或跨版本安装方式。

重建包使用诚实的证明方法 `ROM_ORIGINAL_RECONSTRUCTED_V1`：原 MD5 证据来自保护文件创建时，另记重建来源、原检查时间和私人区域条件，**不声称损坏中的当前 Flash 等于原镜像**。现有完整包格式与读取保持兼容；旧 R11 工具不认识新证明方法，会拒绝。因此新重建包需配套 R12 工具。R12 工具在本轮交付中仍锁真实 USB，仅软件验收。

## 独立产品功能与边界

- 完整备份 / 原系统恢复保持独立入口。需要断网自救、设备故障后的独立副本、长期归档时仍应使用完整包和离线 HTML。其价值没有因减少默认点击而消失。
- 安装保护文件需对应官方资产和恢复工具。未预下载工具时，故障恢复可能需要重新联网获取它们；不能宣称任意断网环境都能从小文件恢复。
- 新系统的厂家设置与配对不迁移；TF 原卡保留。首次安装与重装可以共用入口，但完整清除与 App-only 的授权、保护条件、校验不同。
- 公开前仍需 R12 实机测试和独立产品可用性确认。Windows Chrome/Edge 软件继承 R11 平台门槛；R12 Windows 原生保存/USB/断线处理、Windows 真设备均不可凭 macOS 或合成成绩宣称通过。
- 本轮不开发 Alpha 3.1、跨分区升级、L2 数据迁移、历史版本降级。原系统恢复只恢复已证明的那个原状态，不是新增任意降级器。

## 软件候选运行

`npm ci` 后执行 `node tools/build-r12.mjs dist-r12-software-1 --software`、`node tools/serve-r12.mjs dist-r12-software-1 4231`。从交付源码重建时使用 `SOURCE_IDENTITY.json`。

`--software` 独立适配器只提供合成 ROM 和页面内模拟串口窗口；永不获取真实 `navigator.serial`。不带此参数的 `dist-r12-review-N` 使用拒绝所有连接的适配器。两种产物都没有 CNAME、Pages 部署流程或可公开发布的 R11 profile，不能作为正式发布包。
