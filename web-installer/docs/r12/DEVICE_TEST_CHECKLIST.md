# R12 下一阶段真实设备测试清单（本轮未执行）

所有条目是待验收动作，不是已通过结果。R11 发布可恢复基线保留。先审阅 R12 软件证据，再获得单独真实设备授权和冻结测试构建；不得让本轮锁 USB 的预览临时绕过锁定。优先使用专门验收板；个人板需先确认可恢复状态，必要时沿用已核验完整备份，不机械重备。

## 每个平台独立记录

macOS 桌面 Chrome、Windows 10/11 桌面 Chrome、Windows 10/11 桌面 Edge 分别记录 OS/浏览器版本、串口驱动/设备名、USB 方式、原生保存 API 实际行为、最终回执和普通启动结果。不能合并成一个跨平台 PASS。

## 先只读和文件行为

1. 保存文稿、结束传输；完全断电含电池，取出 TF，只接准确微雪 ST7305；ROM 模式，关串口监视器。
2. 当前发行、芯片、安全、16 MiB、分区/OTA/活动 app0、原 App/bootloader 或准确厂家三段指纹核对。未知、app1、空板继续拒绝。
3. 逐次取消串口选择、保存窗口；拒绝保存权限、模拟磁盘写满/读回失败。全部应无 FLASH_BEGIN/DATA、无自动重连，关闭成功。真实通信/安全异常停止，不自动重试。
4. 原生保存文件名、位置、实际文件长度/SHA、本会话读回是否成功；完整鼠标/键盘/滚动轨迹。普通路径预期 6 点击；特殊系统权限、另选目录、覆盖提示额外计数，不能删掉。

## 两条已知安装路径

1. Alpha 3 app0 同版本：专用样本在 NVS/内部文稿/学习区域及槽尾保留可识别内容；先只读记录受保护区 MD5 和 1,120 字节尾部，不把私人内容放报告。
2. 经明确授权才执行一次重装。必须仅 App 实际扇区写入，保护区 MD5 不变，校验失败立即停止；无 stub、无自动复位。真实 16 MiB 备份不是新的公众强制步骤，但工程验收板应有独立救援基线。
3. 准确厂家样本：验证可变 28 KiB 小文件与原板摘要、官方资产重建整个原系统摘要一致。单独确认完整内部清除，再执行首装；四文件、初始化整片摘要、分区/OTA 校验通过。
4. 串口释放后手动断电、插 TF、正常启动。重装用原键盘通道；首装用备用键盘/备用通道，保留原通道。旧稿只读、新建唯一测试稿、保存、正常重启读取。保留原卡个人数据，不格式化、不覆盖。

## 故障恢复（需另列可损坏试验范围和授权）

1. 专门验收板上分别覆盖擦除刚开始、App 写入中、最后数据完成但校验未完成的断线/断电。首次真实异常按停止条件结束；后续恢复是独立人工授权会话，不能脚本自动重试。
2. 同一个保护文件连接原板；损坏 App 不能从正常安装入口继续。只读重建完整原系统，重建摘要匹配安装前证据。
3. 使用配套 R12 离线工具和实际保存的重建 ZIP，先检查原板身份、完整范围和私人数据回退时间，明确确认一次原系统恢复；独立 Python verify-flash 与浏览器写后验证分别记录。
4. 验证错误原板、错误/损坏保护文件、私人区域变化、官方资产不匹配都停止且零写入。对不可恢复的私人区损坏不得获得 PASS，使用事先独立完整备份救援。
5. 手动普通启动及私人数据检查后，将测试板恢复可使用状态；释放串口，保存脱敏回执，不公开 MAC、私人摘要、包文件或文稿。

## 发布前决策

R12 软件通过不等于 R12 设备通过。特别是新的小型保护策略、原生保存/读回和部分 App 重建恢复需真实样本证据。Windows 真 USB 仍单列 `WINDOWS_DEVICE_PENDING`。厂家官方镜像新增分发方式、版本保留与下载可用性须在实际发布候选审查中核对。未经新的发布授权，不改变当前 R11 网站。
